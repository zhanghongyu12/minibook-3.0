## 1. 设计风格

本章定义全局视觉规范，与 `ARCHITECTURE §11`（暗色模式）完全对齐：颜色一律引用 `MaterialTheme.colorScheme.*` token 与语义 token，页面不散落硬编码色值，token 集中 `ui/theme/Color.kt`。

### 1.1 主题装配与动态配色

- 主题模式三态：`跟随系统 / 手动亮 / 手动暗`（`DarkModeSetting { SYSTEM, LIGHT, DARK }`，存 SettingsDataStore，软切换）。
- `resolvedDark = when(setting) { SYSTEM -> isSystemInDarkTheme(); else -> setting == DARK }`。
- 动态配色：
  - **API 31+**：`dynamicLightColorScheme(context)` / `dynamicDarkColorScheme(context)`（壁纸主题色）。
  - **API 26~30**：内置 `LightColorScheme` / `DarkColorScheme`（M3 默认基线）降级。
- 语义色（收入绿 / 支出红 / 两清灰）不走动态取色，用**静态语义 token**（M3 动态色无法保证收支语义色可区分），亮/暗双值定义见 §1.2。
- 装配点：`MiniBookTheme(darkTheme = resolvedDark, dynamicColor = ...)`，随 DataStore 流 `collectAsState` 软切换，全页面即时生效。
- 系统栏：`enableEdgeToEdge()` + `SystemBarStyle`，状态栏/导航栏自动随 colorScheme 背景与图标对比度切换（沉浸式）。
- 兼容 API 26：低版本动态配色缺省时仅用基线主题，行为仍完整（功能不降级，仅外观不跟壁纸）。

### 1.2 色彩 Token（亮 / 暗双色）

#### M3 角色 Token（基线，API 26~30 降级用；API 31+ 由动态主题覆盖）

| Token | 亮色 baseline | 暗色 baseline | 典型用途 |
|-------|---------------|---------------|---------|
| `primary` | `#6750A4` | `#D0BCFF` | 主按钮、FAB、选中态、链接 |
| `onPrimary` | `#FFFFFF` | `#381E72` | primary 上文字/图标 |
| `primaryContainer` | `#EADDFF` | `#4F378B` | 选中 Chip、品牌背景块 |
| `onPrimaryContainer` | `#21005D` | `#EADDFF` | 容器上文字 |
| `secondaryContainer` | `#E8DEF8` | `#4A4458` | 次级容器、Tab 项 |
| `surface` | `#FEF7FF` | `#141218` | 页面/卡片背景 |
| `onSurface` | `#1D1B20` | `#E6E0E9` | 主文字 |
| `surfaceVariant` | `#E7E0EC` | `#49454F` | 输入框、列表分隔底 |
| `onSurfaceVariant` | `#49454F` | `#CAC4D0` | 次级文字 |
| `outline` / `outlineVariant` | `#79747E` / `#CAC4D0` | `#938F99` / `#49454F` | 边框、未选中态 |
| `error` | `#B3261E` | `#F2B8B5` | 错误提示、删除按钮 |

#### 语义 Token（静态，亮/暗双值，不随动态色改变）

| Token | 亮色 | 暗色 | 用途 |
|-------|------|------|------|
| `semanticIncome` | `#1B7F3B` | `#4ADE80` | 收入金额、收入净额正数、借出/我还款（资产增加方向） |
| `semanticExpense` | `#C62828` | `#FF8A94` | 支出金额、支出合计、借入/收到还款（负债增加方向） |
| `semanticNetZero` | `#79747E` | `#938F99` | 净额为零（两清） |
| `categoryColor` | — | — | 分类自有 `color`（DATABASE §8 种子色值），按原值渲染，不映射 token |

#### 色彩使用铁律

- 页面/组件颜色一律取 `colorScheme` 或语义 token，禁止硬编码色值进 `src/ui/**`（「其他」兜底分类的种子色有唯一例外，读自 DB 数据）。
- 收支符号色统一走语义 token，保证亮/暗双主题下红绿语义不混淆、不依赖动态壁纸。

### 1.3 字体字号

- 字体：系统默认字体（`FontFamily.Default`，Android 原生 Roboto），不引第三方字体（DEC-001 技术栈无字体依赖）。
- 重点：**金额大字使用 tabular figures（`FontFeatureSettings("tnum")`）保证数字等宽对齐**，避免累计金额跳动错位。
- 字号轨（M3 Type 已有 scale + 本项目约定）：

| 应用场景 | Type 风格 | 规格 | 备注 |
|---------|-----------|------|------|
| 首页本月结余（金额大字） | `displaySmall` | 36sp / SemiBold | tabular figures，行首简币符 |
| 页面标题 | `headlineSmall` | 24sp | TopBar 标题 |
| 净额卡片主数字 | `headlineMedium` | 28sp | 债务/收支汇总 |
| 列表主文本 | `bodyLarge` | 16sp（Regular） | 交易 item、分类名 |
| 列表次文本 / 日期分组头 | `bodyMedium` | 14sp | 备注、日期头 |
| 标签 / Chip / 辅助 | `labelMedium` | 12sp | 筛选 Tab、Tab 项、口径说明 |
| 金额行内文本（含符号） | `titleMedium` | 16sp / Medium | 交易行 +/- 金额 |

- 可缩放：随系统 fontScale（保留非等宽字体尺寸变量），结余大字在超大字体下换行不截断（圆角卡片高度自适应，测试覆盖 fontScale ≤ 2.0）。

### 1.4 间距网格

- 基准 4dp 网格，标准 8dp 倍数：

| 层级 | 值 | 用途 |
|------|-----|------|
| `Space 4` | 4dp | 图标内边距、行内紧凑空隙 |
| `Space 8` | 8dp | 列表行间、组件内文本与图标间隙 |
| `Space 12` | 12dp | 卡片内部次级间距、表单字段间距 |
| `Space 16` | 16dp | **页面默认边距**、卡片内容 padding |
| `Space 24` | 24dp | 章节间隔、卡片间主间隔 |
| `Space 32` | 32dp | TopBar 下主区块与内容区距离 |

- 底部导航栏高度 80dp；FAB 距边缘 `16dp`；TopBar 默认 64dp（紧凑高度 56dp 可用于详情头）。
- 触达目标：任意可点区域最小 48dp（被间距与组件高度保证）。

### 1.5 圆角与阴影

- 圆角（M3 `Shapes`）：

| Shape | 值 | 用途 |
|-------|-----|------|
| `small` | 8dp | 输入框、Chip、IconTile、Tab 项 |
| `medium` | 12dp | 卡片、按钮、SegmentedButton |
| `large` | 16dp | 净额卡片、表单单卡、Dialog |
| `extraLarge` | 28dp | BottomSheet 顶部圆角（modal sheet 弹起时顶缘） |
| `full`（圆形） | 24dp | FAB、头像、圆形分类图标 |

- 阴影：主要用 M3 `Elevation` 默认档位——`0`（无阴影，扁平）、`1`（表单浮起）、`3`（FAB / 卡片 hover）、`6`（Sheet / Dialog / Modal）。避免自造多层投影；暗色下阴影不显，靠 `surface` 色阶差表达层级。Ripple 统一 `Material ripple（无边界内）`。

### 1.6 图标与插画

- 图标：Material Icons（vector），跟随 `contentColor/colorScheme` 主题色（不内置彩色图标包）。
- 分类图标：**emoji**（DATABASE §8 种子为 emoji，如 🍜），渲染为彩色圆底 `IconTile`，圆底底色取分类 `color` 的柔和化变体（`color.copy(alpha=0.15)` on 感知背景），emoji 本体原色显示。
- 空态插画：无彩色插画资产，用「大号半透明 icon（`surfaceVariant`）+ 文案」，避免引入图片资源与主题跟随成本。

## 3. 页面设计

> 通用状态约定（各页复用）：
> - **Loading**：首帧骨架屏（色彩块用 `surfaceVariant` 淡化闪烁），不用全局菊花拦截整页。
> - **Empty**：`EmptyState` 组件（图标 + 主文案 + 副文案 + 可选动作按钮）。
> - **Error**：列表 Flow 无数据流错误通道时仅处理两类——账本不存在（`LedgerNotFound` → 引导回账本管理）与解锁/解密异常（全局锁态）；表单类错误就地显示。
> - **边界场景**：金额超限、分类被引用不可删、内置分类禁删、默认账本禁删等，见各页「边界」。
> - 数据源：列表/汇总直接订阅 ViewModel 聚合的 `StateFlow`（`stateIn(WhileSubscribed(5000))`），UI 不直接 collect Room 流（ARCHITECTURE §5.3）。

### P-01 解锁门 LockScreen

**概述**：真解密门。DB 未打开前本页为唯一可达路由，页面不触达任何数据（ARCHITECTURE §7.4 / §9）。

```
┌──────────────────────────────┐
│                              │
│         [App 图标 96dp]        │
│           MiniBook            │
│        「账本已加密锁定」        │
│                              │
│   ┌────────────────────────┐ │
│   │     生物识别解锁          │ │
│   └────────────────────────┘ │
│   [ 使用系统凭据（PIN/密码）]  │
│                              │
└──────────────────────────────┘
```

**交互**：

- 冷启动分诊后若锁开启：直接到达本页（无数据可达）。
- 「生物识别解锁」→ `BiometricPrompt`（`BIOMETRIC_STRONG or DEVICE_CREDENTIAL`），成功回调中 `cryptoObject.cipher` 解出 master key → `DatabaseGate.open` → 进入 home（ARCHITECTURE §7.4 时序）。
- 「使用系统凭据」→ 同一 BiometricPrompt 改用 `DEVICE_CREDENTIAL` 通道。
- 失败/取消：留在本页可重试；多次失败停留锁屏（不降级、不显示任何数据）。

  - UI 上用**二选一 Card（收到还款 | 我还款）**替代裸枚举选择，降低理解成本；贷款方向默认 `owe_me`（借出）。
- 编辑模式：预填全部字段；标题「编辑债务」，含删除（danger ConfirmDialog）。

**状态说明**：

| 态 | 表现 |
|----|------|
| Loading / Empty | 同 P-07 |
| Error | 姓名空 / 金额 ≤0 / 超限：内联错误并禁保存；保存失败 snackbar |
| 边界 | 四态映射严格禁止用户选到"逻辑不可能"组合（`repay` 必选方向）；还款金额可大于原欠款（业务允许，UI 仅提示「金额超过当前净欠额，请确认」，不拦截）|

## 5. 响应式设计

**总体策略：手机竖屏优先（默认目标），大屏/横屏适配用 Material 3 `WindowSizeClass` 断点，MVP 实用主义——只做「对齐与加宽」的降级增强，不做复杂 mResize 重排版**。

### 5.1 断点

| SizeClass | 宽度 | 布局策略 | 落地 |
|-----------|------|---------|------|
| Compact | < 600dp | 单窗：底部 NavigationBar + 全宽 BottomSheet | 默认（手机竖屏） |
| Medium | 600~839dp | 单窗为主，内容区 maxWidth 扩宽（540dp 居中）；Sheet 限宽 560dp | 小平板竖屏 / 大屏手机横屏 |
| Expanded | ≥ 840dp | 双栏可选（见 §5.2）；主内容 ± 侧详情 | 平板/横屏 |

### 5.2 双栏策略（Expanded，MVP 可选增强）

| 页面 | 单窗（Compact） | 双栏（Expanded） |
|------|----------------|------------------|
| 首页 | 纵向串行卡片 | 结余卡 + 最近交易可并排双卡（左主右辅） |
| 收支记录 | 列表全宽 | 左：筛选+列表；右：点选行详情/编辑 inline（替代弹 Sheet） |
| 债务 | Tab 切明细/按对象 | 左：按对象净额列表；右：选中对象的明细流 |
| 设置 | 全宽列表 | 左：设置分区导航；右：分区内容 |
| Sheets | Modal BottomSheet 全宽 | 改为居中 Dialog（maxWidth 560dp）或右侧滑出面板 |

MVP 承诺（控制范围）：
- 五主页交于底部 NavigationBar 在横屏仍可用（不强制换 NavigationRail，列为后续优化）。
- 首个版本实现 `BoxWithConstraints` 阈值（≥840dp）切换双栏，双栏内小屏逻辑复用一个数据源；其余断点仅做边距/宽度约束，不引入双布局代码。
- 宽屏 Stepper 只增不改：`NavigationBar` 位置保持底部；Sheet 在宽屏用 `maxWidth` 约束 + 居中。

### 5.3 横屏专项

- 结余大字与金额行：横屏高度变窄，卡片横向压缩时允许金额折行（`softWrap`），不低于 20sp 最小字号。
- `DateSectionHeader` 与列表行间距按 8dp 网格自适应（不做高度写死）。
- 键盘弹出：底部导航栏自动避让（`imePadding`），Sheet 表单区 `scroll` 可滚，避免金额输入被键盘遮断竖屏。

### 5.4 系统栏与沉浸

- `enableEdgeToEdge()` 全页面开启；状态栏/导航栏色跟随 `colorScheme.background/surfaceContainer`（SystemBarStyle 自动对比图标色）。
- 暗色下系统栏图标自动亮色、亮色下深色，无需页面手动处理。

### 5.5 平铺约束

- 内容最大行宽限制：不设全局 maxWidth（手机不浪费屏宽），只对 Dialog/Sheet 设 maxWidth（560dp）。
- 触达目标 48dp 不随断点缩水；间距网格恒定，仅层次间距（24→32）在 Expanded 放宽。

ReportsScreen (Scaffold)

└─ LazyColumn（图表卡片，每卡独立空态）

**图表「五要素」落地（对应 ARCHITECTURE §15.4，DEC-011）**：

1. **数据口径**：`LineChart / BarChart / DonutChart` 只接收 DB 端/domain 层已聚合数据（`PeriodTrend{ bucket, expenseFen, incomeFen }`、`CategoryAgg{ categoryId, totalFen }`、累计结余序，单位分），**Canvas 不参与任何算术**，只画既得数据点。
2. **坐标系与刻度**：X 轴 = 时间桶（月视图=天 / 年视图=月，等距）；Y 轴 = 金额，`MoneyFormatter` 分→元 + tabular figures；自适应最大刻度 + 网格分隔线（`outlineVariant`），刻度标签不溢出（大额单位化「万/千」缩写）。
3. **图元绘制**：折线 `drawPath`/`drawLine`；柱状 `drawRoundRect`；环形 `drawArc`（sweep 按占比映射 360°）。
4. **图例与交互**：环形旁 `ChartLegend`（色块 + 分类名 + 占比%）；数据点选中高亮为增强项（本期静态渲染不实现）；空态与单点降级（0 数据 → `ChartEmptyState`；1 数据点 → 折线只画点、柱状单柱、环形满圈，不画无意义连线）。
5. **主题配色**：色值取 `MaterialTheme.colorScheme.*` 与语义 token（收入 `semanticIncome` 绿 / 支出 `semanticExpense` 红 / neutral；结余按每点正负取语义色），环形分类色取分类自有 `color`；随暗色软切换。

**交互流**：

- 进入：首页报表入口（设计约定，见 §8.6）→ `reports` 路由；返回 → 首页。
- 月/年切换：TopBar SegmentedButton「月 | 年」→ 月视图按天桶（`observeDailyTrend`）、年视图按月桶（`observeMonthlyTrend`），`flatMapLatest` 重订阅；默认当前月/当前年。
- 分类占比收支切换：图2 下方「收入 | 支出」SegmentedButton → `observeCategoryAgg(type=income|expense)` 切换（PRD「收入/支出分开展示」，一次一张）。
- 点击行为：本期图表静态渲染，无点选详情；图例 hover/点选高亮为增强，不落地本期。
- 返回：系统返回 → 首页。

**状态说明**：

| 态 | 表现 |
|----|------|
| Loading | 图表卡片骨架块（C-05） |
| Empty | 该账本无任何数据 → 每图 `ChartEmptyState`（icon +「暂无数据」），三图均空不崩（PRD F-07 异常处理） |

### 9.2 P-15 导入账单 ImportScreen

**概述**：根图全屏页，route `import`。内容区按 `ImportUiState` 状态机**原地切换**四态：`Idle`（三入口页，2026-10-10 改版）→ `Busy`（全屏忙碌）→ `Result(summary)`（结果）/ `Error(msg)`（错误）。不做结果弹层、不做底部 Sheet。

```
ImportScreen（全屏 Scaffold）
├─ TopAppBar「导入账单」＋ 返回 ←（任何态保留；入口页 = 退出本页，功能结果态 = 回三入口页）
└─ 内容区（when(uiState)）
    ├─ Idle —— **三个入口**（2026-10-10 改版）
    │   ├─ 标题「选择导入方式」（titleMedium）
    │   ├─ 入口卡「账单文件导入」= 标题 + 一行说明（微信/支付宝导出的 .xlsx/.csv）+ Button「选择文件导入」
    │   ├─ 折叠条「▸ 如何导出账单？」（默认收起；展开 = 微信/支付宝两张 PlatformGuideCard C-34）
    │   ├─ 入口卡「邮箱账单自动导入」= 说明 + Button「一键收取邮箱账单」（F-13）
    │   └─ 入口卡「短信账单导入」= 说明 + 两个按钮「增量扫描」（主）/「全量扫描」（次）
    │       + 一行小字「增量＝只看上次扫描之后的新短信；全量＝全部历史（看过的折叠在下面）。」（F-14，L0 → 干跑预览）
    ├─ Busy —— FullScreenBusyOverlay「正在解析账单，请稍候…」（C-20，锁入口/屏蔽返回）
    ├─ Result —— 结果态
    │   ├─ ImportSummaryCard「成功导入 N 笔 / 跳过 M 笔」（C-35）
    │   ├─ SkippedBreakdownSection 分原因 + 解析失败折叠明细（C-36）
    │   └─ Button「完成」→ 回三入口页（Idle）
    └─ Error —— 错误态
        └─ EmptyState（C-04，icon 🔍/⚠ 占位）+ 错误文案 +「重新选择」按钮（回 Idle）
```

**交互流**：

1. **进入**：首页「导入账单」tile（或设置 → 数据 → 「导入账单」行）→ 根图 `import`。入口页返回 →
   `popBackStack` 回来源页；功能结果态返回（顶栏 ← / 系统返回键同语义，`BackHandler` 接线）→ 回
   **三入口页**，可换个方式再导一次；进行中返回 = 退出本页（VM 随返回栈销毁 = 取消本次读取）。
2. **Idle（三入口页）**：三个入口各带一行简短说明，点击各进不同功能；微信/支付宝导出指引折叠进
   「如何导出账单？」，需要时展开（文案与实现同 §9.6）。「选择文件导入」→ 触发 SAF
   `ActivityResultContracts.OpenDocument`（`application/vnd.ms-excel` + `text/csv` + `*/*` 兜底；
   PRD 要求**不唤起第三方 App**）。
   - **SAF 取消**：留在 Idle，无任何提示（用户主动取消非异常）。
3. **Busy**：选文件回 Uri 后立即 `FullScreenBusyOverlay`（C-20）锁数据入口（禁返回 / 禁 Tab，对齐 F-04 导入交互），文案「正在解析账单，请稍候…」。千条级账单期间遮蔽，PRD「期间 UI 锁定数据入口并有进度反馈」以 `CircularProgressIndicator` 满足（不承诺百分比进度，本地 SQLite 毫秒/秒级）。
4. **Result**：`ImportBillUseCase` 返回 `BillImportResult` → 渲染结果态（§9.2 结果态树）：
   - `ImportSummaryCard`：主数字「成功导入 N 笔」，N>0 用 `primary`/`semanticIncome` 强调；「跳过 M 笔」次级行；全跳过（N=0）→ 主数字为「本次无新增交易」（`onSurfaceVariant`，弱化不红）。
   - `SkippedBreakdownSection`：分原因计数（已存在 / 不计收支 / 交易关闭 / 解析失败）；解析失败带**折叠明细**（§9.2 形态说明）。
   - 「完成」→ `onDone` → `popBackStack` 回入口页；首页/收支页交易 Flow 自动刷新（Room Dao 变更触发，无需手动跳转）。
5. **Error**：`Unrecognized` / 解析 IO 异常 / 事务回滚 → `EmptyState` 错误文案 + 「重新选择」回 Idle（原地重置，允许重选，不 `popBackStack`）。

**解析失败明细形态（DEC-020 自决：折叠分组，不一次性平铺、不独立分页）**：

- `SkippedBreakdownSection` 的「解析失败」为**可折叠分组**：默认折叠，表头 `文案「解析失败 N 笔」＋ ▶/▼ 展开指示`；点击展开逐条 `「第 k 行 · 原因」`（k = 文件数据序号/行号，由解析器 `ParseSkippedRow.rowNumber` 提供，见 ARCH §16.3）。
- 选择折叠而非平铺的理由：解析失败是结果的「二等公民」——用户优先关心「成功/跳过」主结论，几十条失败一次性平铺会淹没主结构；折叠实现「先总后分」。
- 选择分组而非滚动弹层/独立分页的理由：结果页整体本就是 `LazyColumn`，展开明细并入同一滚动容器即可（滚动列表），无需多一层 Modal 高度上限（Sheet max 420dp 会被截断）或分页复杂度。
- 边界：解析失败 ≤ 3 条时**默认展开**（少量无折叠必要）；不限总条数（单事务整批写入、结果一次性反馈，行号明细纯展示）。

**状态说明**：

| 态 | 表现 |
|----|------|
| Loading（Busy） | `FullScreenBusyOverlay`（C-20）「正在解析账单，请稍候…」+ `CircularProgressIndicator`；锁入口 + 屏蔽系统返回 |
| Empty | 不适用（导入流程无「无数据」态）；全部跳过走 Result 的「本次无新增交易」分支而非 Empty |
| Error | 见 §9.6 文案表：未识别格式 / 文件损坏 / 事务回滚 → `EmptyState` + 「重新选择」，零落库（ARCH §16.8） |
| 边界 | SAF 取消静默回 Idle；切账本导入落入「当前账本」；导入结果仅一次性展示（Result 态不持久）；「完成」与顶栏 ← 在结果态都回三入口页（不再直接 `popBackStack` 退出本页，2026-10-10 改版） |

**暗色适配**：`PlatformGuideCard` 用 `surfaceVariant.copy(alpha=0.5f)` 底（同 `HomeQuickEntry`）；`SourceBadge` 用 `secondaryContainer`/`onSecondaryContainer`；成功主数字 `primary`（暗色 `#D0BCFF`）/ `semanticIncome`；错误态 icon 沿用 `EmptyState` surfaceVariant 弱化规则；全部 token 化。

### 9.3 新增字段展示（counterparty / paymentMethod / source）

> 三字段语义（PRD §F-12 / DEC-018）：`source` 恒非空（默认 `manual`）；`counterparty`/`paymentMethod` 可空（手动记录恒 null）；`description` 不再承载支付方式。**金额语义色规则不变**——以下所有插入均不触碰 `MoneyText` 的收绿/支红语义。

#### 9.3.1 `TransactionListItem`（C-13 增强）

在现有 `Row [分类圆底 | Column(分类名, 描述) | Column(金额, 日期)]` 结构上的插入位与样式：

1. **`counterparty`（交易对方）→ 副文本第 1 行**：把现有「描述」副文本槽升级为「0~2 行副文本」——自上而下先 `counterparty` 后 `description`，各自 `bodySmall + onSurfaceVariant + maxLines=1` 省略，均 `isNotBlank()` 才渲染、都空则无副文本区。理由：账单里「对方/商家」辨识度高于「商品说明」，故对方在前；描述退为第 2 行（现有单行描述语义保持向下兼容，手动记录无 counterparty 时回退为「仅描述一行」）。
2. **`source`（来源徽标）→ 分类名主文本行尾部**：`Text(categoryName)` 由裸 `Text` 改为 `Row { Text(categoryName, weight(1f), ellipsis) + SourceBadge(标签) }`。仅 `source ≠ MANUAL` 时渲染 `SourceBadge`（C-33，文案「微信 / 支付宝」）；手动记录不渲染（零噪音）。徽标 `labelSmall`、`secondaryContainer` 圆角底 + `onSecondaryContainer` 字、左右 `6dp` / 上下 `2dp` 内边距；挤占分类名宽度时分类名省略，可接受（分类名通常短、徽标 2 字极窄）。
3. **`paymentMethod` → 列表行不展示**（信息密度控制，支付方式属低频关注，留给详情）；避免行高失控。

> 金额 / 日期 / 语义色的右列 Column、分类圆底色规则**一概不动**。

#### 9.3.2 `TransactionDetailSheet`（交易只读明细，ui/search，P-12 复用）

在既有 `DetailRow` 序列中，于「日期」之后、「备注」之前**聚簇插入 3 行**（导入字段作为独立信息块，不动「类型→金额→分类→日期→备注」主线）：

| 标签 | 值 | 空值占位 |
|------|-----|---------|
| 对方 | `tx.counterparty` | `—` |
| 支付方式 | `tx.paymentMethod` | `—` |
| 来源 | 「手动记录 / 微信 / 支付宝」（`source` 中文映射，恒显示） | — |

样式沿用 `DetailRow(label, value)`（label 定宽 80dp、`onSurfaceVariant`；value 弹性），空值用 `—` 且 `onSurfaceVariant` 弱化（同「备注」空值兜底）。

#### 9.3.3 `TransactionSheet`（记一笔/编辑态的展示，P-07）

导入带入的三字段属**只读展示**（不可编辑）：当 `tx.source ≠ MANUAL`（或 counterparty/paymentMethod 任一非空）时，在表单金额区与「分类」之间加一个**只读信息块**：单行 `bodySmall + onSurfaceVariant` 文案——`「来源：微信 · 对方：张三 · 支付方式：零钱」`（空字段跳过对应段）。手动记录（source=manual 且两字段空）不显示该块（零噪音，记一笔新增/编辑手动交易时形态与现状完全一致）。

> 记一笔新增路径恒 `source=manual、counterparty/paymentMethod=null`（DEC-018：`AddTransactionUseCase` 零改动），故该只读块**只会在编辑导入交易时出现**。

### 10.2 P-16 邮箱凭据设置页 MailSettingsScreen

**概述**：根图全屏页，route `mail_account`。承载**多个** QQ 邮箱账号（地址 + IMAP 授权码）的列表、新增、编辑与删除；持久化全委托 `MailAccountStore`（`accounts: StateFlow<List<MailAccount>>` 列表 + `suspend upsert/delete/getAuthCode`，校验 + Keystore 加密落盘，API §14.1）。页面两态：**列表态**（默认）与**编辑态**（新增 / 修改单个账号）。

```
MailSettingsScreen（全屏 Scaffold）
├─ TopAppBar「邮箱凭据」＋ 返回 ←
└─ 内容区（Column，verticalScroll）
    ├─ 配置指引文案（bodyMedium，onSurfaceVariant）
    ├─ ⚠ IMAP/SMTP 强调文案（bodyMedium 加粗，error 色）
    ├─ 列表态
    │   ├─ 账号行 ×N（邮箱地址 + 尾部 TextButton「删除」）
    │   ├─ 空态提示（0 个账号时）
    │   └─ OutlinedButton「添加邮箱」→ 切编辑态
    └─ 编辑态（新增或修改某账号）
        ├─ OutlinedTextField「邮箱地址」（KeyboardType.Email，单行）
        ├─ OutlinedTextField「IMAP 授权码」（默认 PasswordVisualTransformation 掩码，
        │   尾部 TextButton「显示/隐藏」切换）
        ├─ 行内错误提示（errorMessage 非 null 时，error 色，不崩溃）
        ├─ Button「保存」（编辑已有账号时文案「保存（更新）」）
        └─ TextButton「取消」→ 回列表态
```

**交互流**：

1. 进入：导入页未配置态「去配置」或设置页「邮箱凭据」行 → 根图 `mail_account`；返回 `popBackStack`。
2. 新增：列表态「添加邮箱」→ 编辑态（输入清空）→ 保存委托 `MailAccountStore.upsert`——邮箱格式非法或授权码非 16 位时行内展示中文错误（来自 Store 的 `IllegalArgumentException.message`，仅格式描述与长度数字，不含凭据内容）；其余异常折叠为「保存失败，请重试」。
3. 修改：点账号行 → 编辑态（预填邮箱、授权码留空需重填）→ 保存覆盖该账号（`upsert` 按 id 更新）。
4. 保存成功：Snackbar「已保存」（`MiniBookSnackbarHost` C-21）+ 回列表态且账号数即时刷新（设置页尾部徽标同源）。
5. 删除：账号行「删除」→ `ConfirmDialog`（C-18 danger 变体）强确认 → `MailAccountStore.delete(id)` 抹掉该账号的密文凭据文件；删除失败不阻塞列表刷新，不写日志。

**状态说明**：

| 态 | 表现 |
|----|------|
| Loading | 不适用（初值从 Store StateFlow 构造时同步读出，无异步等待） |
| Empty | 0 个账号：列表态展示空态提示 + 「添加邮箱」，不报错 |
| Error | 校验失败行内中文（邮箱格式 / 授权码位数），不崩溃、不清空输入，允许即时改错重试 |
| 边界 | 授权码仅存内存 + 每账号独立密文文件落盘（`noBackupFilesDir`），绝不进日志/异常；页面可滚动（`verticalScroll`）容纳小屏键盘遮挡 |

**暗色适配**：全部沿用 `colorScheme` token（输入框 `surfaceVariant` 底、强调文案 `error`、指引 `onSurfaceVariant`），无新增色值。

### 10.3 进度 / 结果 / 错误「同页合一」与精确中文文案

`ImportUiState` 在 F-12 四态（Idle/Busy/Result/Error）基础上新增 5 态（API §14.8）：`MailBusy(progress)`、`MailResult(summary, progress)`、`MailChooseAccount(accounts)`（多邮箱选择弹窗）、`MailNotConfigured`（未配置引导）、`MailError(message, progress)`（认证/网络/未预期）。

**「同页合一」是硬口径**：`MailBusy` / `MailResult` / `MailError` 三态**统一渲染同一个 `MailImportContent`**——收取中实时推进 stepper，结束后**原地追加**结果摘要 / 失败明细 / 错误卡，**成功或失败都不切换页面、不整体替换版式**（用户 2026-09-23 明确要求）。页面结构 = 单一 `Column`：`weight(1f)` 的 `verticalScroll` 内容区（进度区 → 结果区 → 错误区，按状态出现）+ 钉在屏幕底部的「重新选择 / 返回」按钮区（`running = true` 时不渲染）。仅 `MailNotConfigured`（收取前的引导态）与 F-12 的 SAF 文件导入各态使用各自版式。

**进度结构**：多邮箱头部 `邮箱 k/N · {email}` → 5 步竖向 stepper（`○` 待执行 / 转圈 进行中 / `✓` 完成 / `✗` 失败；完成与失败均附中文摘要）→ 第 4 步展开区（`第 i/N 封 · {邮件主题}` + 当前子步骤 + CRACK 口令穷举百分比）→ 逐封结果行卡（`✅/❌ {平台} · {邮件主题} — {结果}`，卡内独立滚动上限 200dp）→ 结果 / 错误区。

**步骤状态累积**：`MailBillImportUseCase` 经 `MailImportStepTracker` 发**累积**快照——已发出的步骤状态在后续快照中保持，不会把已完成步骤打回 `○`（修复前真机收取成功后会显示 `○○○○✓`）；每个账号一份实例（多账号时头部 `邮箱 k/N` 推进、stepper 从头开始）。**被跳过的账号也发快照**（`连接邮箱` 标 `✗` + 原因），不再静默。
