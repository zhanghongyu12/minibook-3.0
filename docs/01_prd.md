## 1. 产品概述

### 产品定位
MiniBook 是一款**纯 Android 原生**的个人记账应用，本地优先、隐私优先。在原有 MiniBook（Taro 多端版）基础上重构：仅保留安卓端，前端用 Kotlin + Jetpack Compose 完全重写，本地存储用 Room(SQLite) 重新选型。云端同步本期不做，仅预留数据源出口。

### 产品目标
- 短期：在安卓端提供与旧版一致且更流畅的记账体验，并补齐搜索、报表、预算、暗色模式、数据加密、多账本等增强能力
- 长期：预留云端同步出口，未来可平滑接入多设备同步

## 2. 目标用户

| 用户类型 | 特征 | 核心需求 |
|---------|------|---------|

| 家庭/多场景用户 | 一套账不分家、需要多本账 | 多账本隔离、可切换 |

## 5. 用户场景

### 场景 1：记一笔支出
**前提条件：** 已启动应用并解锁
**操作流程：** 首页点「记一笔」→ 选支出 → 输入金额 → 选分类 → 填备注（可选）→ 保存
**预期结果：** 交易入库，首页结余与最近交易即时刷新

### 场景 2：记一笔借款并收款
**操作流程：** 债务页 → 新增「借出」张三 500 元 → 之后新增「收到还款」张三 200 元
**预期结果：** 张三净欠款显示 300 元

### 场景 3：导出备份
**操作流程：** 设置页 → 导出 → 生成 JSON 文件
**预期结果：** 得到含全部数据的 JSON，可导入还原

### 场景 4：应用锁
**操作流程：** 开启应用锁并设超时 → 离开超时后回来
**预期结果：** 需生物识别验证通过才可查看数据

### 场景 5：多账本切换
**操作流程：** 创建「家庭」账本 → 切换 → 记录一笔支出
**预期结果：** 该支出只出现在「家庭」账本，与「默认账本」互不影响

## 6. 功能需求详情

### F-01 收支记录
**输入：** 类型（收入/支出）、金额（元，转分存储）、分类、日期、备注（≤200 字）
**验收标准：** 金额以整数分存储无精度损失；首页显示本月结余/收支合计/最近交易；收支页可按全部/支出/收入筛选，按日期分组
**异常处理：** 金额 ≤ 0 拒绝保存；分类未选则提示

### F-02 债务管理
**输入：** 对方姓名、金额、类别（欠款/还款）、方向（借出/借入）、日期、备注
**验收标准：** 借/还平级模型（kind × direction）；明细视图按时间排序；按对象视图按人汇总净额；净额口径「借出+、借入−、收到还款−、我还款+」
**异常处理：** 姓名为空、金额 ≤ 0 拒绝保存

### F-03 分类管理
**验收标准：** 内置分类（12 支出 + 6 收入）不可删除、可改图标/颜色；自定义分类可增删改
**异常处理：** 删除分类时若有关联交易，提示迁移到其他分类

### F-04 数据导入导出
**验收标准：** 导出 JSON（version 1 格式，含 transactions/debts/categories/budgets/ledgers）；导入全量覆盖、事务原子性、字段校验
**异常处理：** 导入数据字段缺失/非法时报错不落库

### F-05 应用锁
**验收标准：** 生物识别（指纹/人脸）+ 系统凭据回退；冷启动恒锁；离开超时重锁（立即/30s/1min/5min/永不）
**异常处理：** 设备无解锁方式时提示不支持

### F-06 搜索（Phase 2）
**输入：** 从首页顶部搜索入口进入独立搜索页；搜索范围限定当前账本（不跨账本，符合 F-11 隔离）。条件字段分两组——交易：备注关键词、金额区间（min/max）、分类、日期区间、类型（收入/支出）；债务：姓名关键词、方向（借出/借入）。
**验收标准：** 结果分「交易/债务」两组；交易按备注模糊（含关键词即命中）+ 金额区间（min/max，单位分）+ 分类 + 日期区间 + 类型（收入/支出）组合过滤；债务按姓名模糊 + 方向（借出/借入）过滤；结果按时间倒序；点击结果展示不可编辑的明细。
**异常处理：** 无结果显示空态提示；金额区间 min > max 时拒绝或视为无效。

### F-07 报表统计（Phase 2）
**输入：** 统计范围限定当前账本（不跨账本）；支持月度/年度视图切换；金额口径复用已有 monthSummary/countByCategory 的整数「分」口径。
**验收标准：** 月度视图按天、年度视图按月；三类图——①收支趋势（月度按天、年度按月，折线或柱状）②分类占比（环形/饼图，收入/支出分开展示）③结余走势。
**异常处理：** 该账本无任何数据时显示空态。

### F-08 预算管理（Phase 2）
**输入：** 月度总预算（分类为空，整月）+ 分类预算（指定 categoryId）；金额单位整数「分」。
**验收标准：** 已用 = 当月该分类实际支出累计（分）；剩余 = 预算 − 已用（分）；超支 = 已用 > 预算；展示已用/剩余进度；超支时给出本地提醒（通知栏或页内形态，具体由 Architect DEC-011 决策；本需求只锁「必须在本机提醒超支、不依赖云端」）。
**异常处理：** 预算金额 ≤ 0 或未选月份拒绝保存；分类预算与总预算可并存不冲突。

### F-09 暗色模式
**验收标准：** 跟随系统 / 手动亮暗切换，全页面生效

### F-10 数据加密
**验收标准：** 本地数据库整体加密（SQLCipher）；密钥由 Android Keystore 保护；生物识别通过后取密钥解密打开数据库
> 说明：与 F-05 联动，应用锁从旧版「防偷瞄遮罩」升级为「真实解密门」。

### F-11 多账本
**验收标准：** 默认一个「默认账本」；可创建/切换多个账本；交易/债务/分类/预算按账本隔离；每账本独立统计与导入导出
> 说明：此处「多账本」指同一用户的多本账（个人/家庭/生意），不含登录/多用户账号体系。

### F-12 微信/支付宝账单导入

> 本功能原拟编号 F-09，因 F-09 已被「暗色模式」占用、F-06~F-11 均已分配，顺延定为 **F-12**（见 DEC-015）。

**输入：** 支付宝账单 `.csv`（GBK 编码，「交易流水证明」导出件）或微信账单 `.xlsx`（「账单明细」导出件）；入口位于首页或「记一笔/收支」页的「导入账单」（具体位置由 Designer 定，PRD 只给入口层级）。

**入口层级与操作提示：** 点入「导入账单」先展示操作提示页，说明两平台手动导出路径——
- 微信：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 用于个人对账
- 支付宝：我的 → 账单 → 右上「⋯」→ 开具交易流水证明 → 用于个人对账

随后进入系统文件选择器（SAF `ACTION_GET_CONTENT` / `ACTION_OPEN_DOCUMENT`）选文件；**不做跳转唤起第三方 App**。

**数据模型变更（`transactions` 新增 4 列）：**

| 新列 | 类型 | 约束/默认 | 是否展示 | 说明 |
|------|------|-----------|:---:|------|
| `externalId` | String? | NULL；唯一索引 `UNIQUE(ledgerId, externalId)` | 否 | `alipay:<交易订单号>` / `wechat:<交易单号>`；手动记录恒 null |
| `counterparty` | String? | NULL | 是（列表行/详情） | 交易对方/商家 |
| `paymentMethod` | String? | NULL | 是 | 支付方式（花呗/零钱/银行储蓄卡等） |
| `source` | String | NOT NULL 默认 `manual` | 是 + 可筛选 | `manual` / `wechat_import` / `alipay_import`，界面中文「手动记录 / 微信 / 支付宝」 |

> `description` 仅承载「商品说明 + 备注」，**不再放支付方式**。

**字段映射（账单 → MiniBook）：**

| 账单字段 | MiniBook 字段 | 规则 |
|---|---|---|
| 交易时间 | `date` | 仅取日期 `yyyy-MM-dd`（时分秒丢弃） |
| 收/支 | `type` | 支出→`expense`、收入→`income`；「不计收支」/「/」/空→跳过 |
| 金额(元) / 金额 | `amount` | 字符串→`BigDecimal`→`setScale(2)`→`movePointRight(2)`→`longValueExact()` 转分，**禁 float/double 乘法** |
| 交易对方 | `counterparty` | 原样落库 |
| 支付方式 / 收/付款方式 | `paymentMethod` | 原样；空/全空白→null |
| 商品说明 / 商品 | `description` | 主内容 |
| 账单「备注」 | `description` | 非空且 ≠「/」时以 `｜` 分隔追加（DEC-015） |
| 交易订单号 / 交易单号 | `externalId` | `alipay:` / `wechat:` 前缀包裹原单号 |
| 平台分类（交易分类/交易类型） | `categoryId` | 经自动分类映射预填（见下），原始分类**不存储** |

> 不落库：微信「当前状态」（仅参考）、「对方账号」、「商户单号 / 商家订单号」。

**解析规则：**
1. **动态表头探测**：不写死跳行数/行号。逐行扫描直至命中「表头行」——同一行同时含「交易时间」「收/支」及「金额」或「金额(元)」关键词——记下列索引，其后为数据行；前导说明行（导出信息/统计/提示等）数量变化不影响解析。
2. **支付宝**：GBK 解码；交易订单号、商家订单号字段尾部 `\t` 需 trim。
3. **微信**：读取 XLSX 内 `xl/sharedStrings.xml`（`t="s"` 单元格反查共享字符串）与 `xl/worksheets/sheet1.xml`；「交易时间」为 Excel 日期序列数（如 `46257.7435…`），按「整数部分 = 距 1899-12-30 的天数」换算（`LocalDate.of(1899,12,30).plusDays(整数天数)`），落库仅取日期、时分秒丢弃，全程字符串/整数拆分、**禁 double**；「金额(元)」为数值单元格，按 `<v>` 文本字面量读入（不 parse 为 double）再转分。

**过滤规则（导入时丢弃，不落库，分原因计数）：**
- 收/支 = 「不计收支」（支付宝）/「/」（微信中性）/空 → 跳过（计「不计收支」）
- 支付宝 交易状态 = 「交易关闭」→ 跳过（计「交易关闭」）；实测「退款成功」「还款成功」均带收/支「不计收支」，已被上条覆盖，无需额外规则
- 解析失败（时间缺失 / 金额非法或非正 / `externalId` 对应单号为空等）→ 跳过（计「解析失败」，给出行号与原因）

**幂等去重：** `externalId` 唯一冲突（`UNIQUE(ledgerId, externalId)`）→ 跳过该行（计「已存在」）；手动记录 `externalId=null` 不参与冲突（SQLite 唯一索引对 NULL 视为互异）。

**自动分类预填：**

| 平台 | 平台分类 | 收/支 | 目标内置分类 |
|---|---|:---:|---|
| 支付宝 | 餐饮美食 | 支出 | 餐饮 |
| 支付宝 | 交通出行 | 支出 | 交通 |
| 支付宝 | 日用百货 | 支出 | 购物 |
| 支付宝 | 服饰装扮 | 支出 | 服饰 |
| 支付宝 | 文化休闲 | 支出 | 娱乐 |
| 支付宝 | 运动户外 | 支出 | 娱乐 |
| 支付宝 | 酒店旅游 | 支出 | 旅行 |
| 支付宝 | 家居家装 | 支出 | 住房 |
| 支付宝 | 医疗健康 | 支出 | 医疗 |
| 支付宝 | 教育培训 | 支出 | 教育 |
| 微信 | 微信红包 / 微信红包（单发） | 支出 | 人情 |
| 微信 | 微信红包 / 微信红包（单发） | 收入 | 礼金 |

- **未列入上表的任何「平台分类 × 收/支」组合**（含支付宝「退款/信用借还/投资理财/商业服务/生活服务/美容美发/其他」、微信「商户消费/扫二维码付款/转账/群收款/二维码收款/零钱提现/各退款/其他」等）**一律 → 该 `type` 的「其他」内置分类**；映射表可扩展。
- **解析机制**：映射产物为「目标内置分类名」，导入时按「当前账本内 `type` 匹配 + `name` 精确匹配」解析为 `categoryId`；解析不到（内置分类被改名/删除、或无映射）→ 回退该 `type` 的「其他」内置分类（「其他」名称按 DEC-007 锁定，恒可定位作兜底锚点）。分类为**预填**，用户可事后改名/改分类。

**导入结果反馈：** 一次性反馈「成功导入 N 笔、跳过 M 笔」，其中 M 分原因展示：已存在 / 不计收支 / 交易关闭 / 解析失败（解析失败逐条给出文件行号与原因）。

**一致性与事务（DEC-015 口径）：** **「逐行过滤 + 单事务整批写入」**——过滤/幂等跳过是行级语义（逐行判定、计数反馈，非失败）；通过过滤的有效交易行在**单事务**内整批插入，任一真实写入异常（非跳过类）→ 整体回滚、零落库、报错。理由：过滤/去重本质行级（本需求 #7/#8 已锁），写入一致性沿用 F-04 已确认的「单事务原子性」口径，避免「半导入」脏数据中间态；千条级本地 SQLite 单事务性能足够。

**验收标准：**
- [ ] 两种文件（支付宝 GBK CSV / 微信 XLSX）均可成功解析；非目标格式或表头探测失败 → 报「未识别账单格式」，零落库
- [ ] 动态表头探测不依赖前导行数：增删说明行仍能定位表头；支付宝 `\t` 尾随被 trim
- [ ] 微信日期序列数正确换算为 `yyyy-MM-dd`；金额经 BigDecimal 转分无精度损失（如 `8.70`→870、`6.5`→650）
- [ ] 字段映射逐项正确：`type/amount/counterparty/paymentMethod/description/externalId/categoryId` 与上表一致；微信「当前状态/对方账号/商户单号」不落库
- [ ] 过滤规则逐条生效且计数正确（不计收支/交易关闭/解析失败各分类计数）
- [ ] 幂等：重复导入同一账单，已存在行全部跳过（计「已存在」），不产生重复行；手动记录（externalId=null）不受影响
- [ ] 自动分类预填正确，映射失败归对应 type 的「其他」；用户可事后改名/改分类
- [ ] 结果页展示「成功 N / 跳过 M（分原因）」；解析失败给行号与原因
- [ ] 事务原子性：注入写入异常 → 整体回滚零落库（复用 F-04 原子口径）
- [ ] 千条级账单导入流畅、期间 UI 锁定数据入口并有进度反馈

**异常处理：**
- 文件损坏 / 非 CSV(GBK) 或非 XLSX → 报错不落库
- 表头未命中（无「交易时间」等关键词）→ 报「未识别账单格式」
- 全部行被跳过（无新增）→ 提示「本次无新增交易」及跳过明细
- 金额为 0 / 负 / 非数字 → 该行按「解析失败」跳过（与既有「金额>0」口径一致）

### F-13 邮件账单自动导入（Phase 3）

> 本功能是 **F-12 的取件自动化前置段**：把「平台发到邮箱的账单邮件」自动取出来、解开、喂给 F-12 既有解析链路。**不替换 F-12 任何逻辑**（详见 `12_mail_bill_import.md`）。

**输入：** QQ 邮箱地址 + **IMAP 授权码**（用户在 QQ 邮箱网页版「设置→账号→IMAP/SMTP服务」生成；**不是**登录密码）。

**用户操作：** 设置页填一次邮箱凭据 → 之后在导入页点「**从邮箱一键收取**」。**全程无需输入任何解压密码。**

**处理链路：**
1. IMAP 连接 `imap.qq.com:993`（SSL，含客户端 `ID` 命令），**只读**打开收件箱。
2. 拉取最近 N 天邮件（默认 30 天）→ **本地过滤**账单邮件：
   - 支付宝：发件人 `service@mail.alipay.com`，主题含「支付宝交易流水明细」
   - 微信：发件人 `wechatpay@tencent.com`，主题含「微信支付-账单流水文件」
   > **禁止依赖 IMAP 服务端 SEARCH**——实测其在本场景返回 0 结果（见设计文档 §2.1）。
3. 取件：
   - **支付宝**：下载邮件附件（文件名经 RFC2047/RFC2231 编码，需解码）
   - **微信**：正文**没有附件**，需从正文提取下载链接（`tenpay.wechatpay.cn/.../downloadfilefromemail?<签名 token>`）后 HTTPS 下载；**链接有效期 7 天**
4. 解密：对加密 zip **自动穷举 6 位数字口令**（→ 见下「解压口令」），ZipCrypto 解密 + 解压。
5. 解出的 `.csv`(GBK) / `.xlsx` 交给 F-12 既有 `ImportBillUseCase`（自动分类 + `externalId` 去重 + 单事务整批写入）。

**解压口令（关键）：**
- 两平台的解压口令**都不随邮件发送**（支付宝在支付宝 App 服务消息、微信在【微信支付】公众号），按常理必须用户手动输入。
- **实测确认：口令恒为 6 位纯数字，且每次不同**（三封真实账单实测均命中；**口令属凭据，一律不落文档**），穷举空间 `10^6`，PC 上约 1 秒。
- 因此本功能采用「**本地自动穷举口令**」实现真正的一键，无需用户输入；**不得**采用「让用户输入一次并记住」方案（口令每期变化，记住无效）。
- 穷举失败（口令非 6 位数字）或加密方式非 ZipCrypto（如 AES）→ **明确报错、不得静默失败**；当前实现为记录失败原因并在结果页逐封提示（**手动输入口令 UI 未实现，属后续增强**）。

**数据与隐私边界：**
- 邮箱授权码用 Android Keystore（AES-256/GCM）加密落盘；**口令/凭据/账单内容一律不进日志**。
- 邮件**只读**：不删除、不标已读、不移动、不改任何 flag。
- 出网点仅 `imap.qq.com:993` 与 `tenpay.wechatpay.cn:443`（均 TLS）；**不上传任何用户数据**，不接统计/上报 SDK。
- 临时文件（zip、解出账单）只落 `cacheDir`，导入结束（含失败路径）`finally` 删除。

**验收标准：**
- [ ] 填对邮箱 + 授权码后可成功连接并列出账单邮件数；授权码错误给出明确提示（不泄露凭据）
- [ ] 支付宝账单邮件：能下载附件并正确解码 RFC2047 中文文件名
- [ ] 微信账单邮件：能从正文提取下载链接并成功下载 zip；链接过期/失效给明确提示
- [ ] 加密 zip 能自动穷举出 6 位数字口令并解压；穷举失败降级为手动输入
- [ ] 解出的账单进入 F-12 链路后，成功/跳过计数与手动导入同一账单**完全一致**（同 `externalId` 去重口径）
- [ ] 全程只读邮箱：收取前后邮件数量、已读状态、位置均不变
- [ ] 凭据加密落盘（非明文），日志中检索不到授权码/口令
- [ ] 收取过程有进度且可取消；失败不产生半导入数据

**异常处理：**
- 授权码错误 / IMAP 服务未开启 → 「登录失败」提示（附排查指引：需开启 IMAP/SMTP 服务而非仅 POP3）
- 网络不可达 / 超时 → 「网络异常」提示，可重试
- 近 N 天无账单邮件 → 「未找到账单邮件」提示（附各平台申请入口指引）
- 微信下载链接过期（>7 天）→ 提示「链接已过期，请在微信重新申请」
- 口令穷举失败 / 加密类型不支持 → 提示并引导手动输入口令
- 解出文件仍无法解析（格式变化）→ 复用 F-12「未识别账单格式」错误，零落库

### F-14 短信账单导入（Phase 3）

> 本功能是 **F-12 的第三条取件通道**（三条：F-12 账单文件 / F-13 邮件账单 / F-14 短信）：把「手机短信里的银行/支付账单」解析成交易，喂给 F-12 既有解析与入库链路。**不替换任何既有逻辑**（完整设计见 `13_sms_bill_import.md`）。

**输入：** 手机短信（`content://sms`，收件箱为主）；**无需用户提供任何凭据**。

**用户操作：** 设置页开启「短信账单」总开关 → 按需开启「实时识别新短信」→ 之后：① 导入页点「**读取短信账单**」做一次扫描；② 或由新到短信自动进入「待确认」（默认静默聚合，不弹通知）；③ 白名单发送方可自动记账。

**处理链路：**
1. **读取**：`ContentResolver` 按 `date ASC, _id ASC` 分页读取（防 CursorWindow 溢出）；记录水位（`max(_id)`/`max(date)`）用于增量扫描与补扫。
2. **过滤/解析**：按「发送方号码 + 抬头锚点」匹配模板，结构化抽取 时间/金额/方向/卡尾号/渠道/商户/余额 → 统一 `ParsedBillRow`；`externalId = sms:<内容哈希>`（**短信普遍无交易单号**）。
3. **去重**：同源由 `UNIQUE(ledgerId, externalId)` 幂等；**跨源**（与账单文件/邮件）按「同账本 + 同方向 + 金额相等 + 日期相同」匹配——唯一候选自动判重、多候选人工确认、**永不自动删除**。
4. **入库**：复用 F-12 `ImportBillUseCase`（单事务整批 + `IGNORE` 幂等），不新建第二条写库路径。
5. **校验**：四类计数闭合（`扫描数 = 命中 + 未识别 + 非账单 + 去重/已存在`）+ 余额链缺口检测。

**自动化与开关（全部默认关闭）：**
- 总开关关闭时**不申请任何短信权限**；
- 实时识别：`SMS_RECEIVED` 广播（**非默认短信应用即可接收**，不抢 `ROLE_SMS`）；默认**静默聚合**（只在 App 内「待确认」累积）；
- 自动记账：仅「白名单发送方 + 模板命中 + 判无重复 + 渠道允许自动」**四条件同时成立**；白名单由「用户手动确认 3 次且无纠错」晋级、纠错即降级、逐项可关；
- 补扫：打开 App / 解锁 / 手动刷新时按水位增量补扫（覆盖关机、后台被清理、广播丢失）。
- 已知限制：**应用锁开启**时后台无法解密开库 → 自动记账降级为「待确认 + 解锁后补记」；经支付宝/财付通渠道的短信**默认只提醒不自动记账**（这些必被账单文件覆盖）。

**数据与隐私边界：**
- 只读：不删除、不修改、不标记已读任何短信；不申请默认短信应用角色；不申请 `SEND_SMS`。
- 识别成功的短信**原文不落库**（只存抽取结果）；未识别样本可本地保留（默认 **30 天**后清理、可一键清空）；日志与通知**不得**出现原文、卡号全文与余额。
- 新增权限 `READ_SMS` / `RECEIVE_SMS` / `POST_NOTIFICATIONS`，**均可独立拒绝**；全部被拒时降级为「分享导入」（**零权限**）。
- **无新增第三方依赖、无数据库 schema 变更、零上云**。

**验收标准：**
- [ ] 总开关关闭时，App 不申请任何短信权限（清单与运行时两层核对）
- [ ] 扫描满足四类计数闭合：`扫描总数 = 命中 + 未识别 + 非账单 + 去重/已存在`
- [ ] 同源重复（重扫同一短信、重导同一账单）不产生新记录
- [ ] 跨源重复可识别：先导账单后扫短信、先扫短信后导账单**两个方向**均能判重（唯一候选自动、多候选进人工确认）
- [ ] 未识别短信**入清单可见**（不静默丢弃），可手工转一笔 / 标记非账单 / 导出样本
- [ ] 实时识别：非账单短信（验证码/营销/快递）**零提醒**；账单类进「待确认」且默认不弹通知
- [ ] 自动记账仅在四条件成立时发生，每笔可撤销；用户纠错后该发送方立即降级
- [ ] 应用锁开启时自动记账入口置灰并给出原因
- [ ] 余额链缺口可被检出并给出时间区间提示
- [ ] 日志与通知中检索不到短信原文/卡号/余额

**异常处理：**
- 权限被拒 / 被系统「受限设置」挡住 → 明确提示 + 「去系统设置」+「改用分享导入」
- 短信库为空或无命中 → 「没有可导入的短信账单」+ 说明（附账单文件/邮件通道指引）
- 模板未命中 → 计「未识别」并留痕，**不得**静默跳过
- 解析出金额 ≤ 0 / 方向不明 → 计「未识别」（不落库）
- provider 读取异常（ROM 限制）→ 明确报错可重试，**不影响 F-12/F-13 任何路径**

## 7. 非功能需求

### 性能
- 冷启动（含解锁）：≤ 2 秒
- 交易/债务列表滚动流畅（千条级数据）

### 安全
- 数据库加密（F-10），密钥 Keystore 保护
- 生物识别解锁（F-05）

### 数据一致性
- 金额全程整数「分」，避免浮点误差
- 导入导出事务原子性

### 离线可用
- **除 F-13 邮箱账单拉取外**，所有功能离线可用，无网络依赖（本期无云端）
- F-13 的网络面是**单向拉取**（IMAP 取账单邮件 + HTTPS 下载账单 zip），**不上传任何用户数据**、不接统计/上报 SDK；**不做后台联网**（仅在用户点击「一键收取」时执行）；断网时 F-12 手动导入路径完全不受影响
  > 本条为 DEC-023 修订：F-13 是本项目**首个引入网络与外部凭据**的功能，故对原「无网络依赖」做显式例外化，而非默认放宽。

### 兼容性
- Android 8.0（API 26）及以上
