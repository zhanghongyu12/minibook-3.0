# MiniBook Android 重构版 - 产品需求文档 (PRD)

> 状态：评审中
> 最后更新：2026-08-21
> 维护者：PM

## 1. 产品概述

### 产品定位
MiniBook 是一款**纯 Android 原生**的个人记账应用，本地优先、隐私优先。在原有 MiniBook（Taro 多端版）基础上重构：仅保留安卓端，前端用 Kotlin + Jetpack Compose 完全重写，本地存储用 Room(SQLite) 重新选型。云端同步本期不做，仅预留数据源出口。

### 产品目标
- 短期：在安卓端提供与旧版一致且更流畅的记账体验，并补齐搜索、报表、预算、暗色模式、数据加密、多账本等增强能力
- 长期：预留云端同步出口，未来可平滑接入多设备同步

## 2. 目标用户

| 用户类型 | 特征 | 核心需求 |
|---------|------|---------|
| 个人用户 | 重视隐私、需离线可用 | 记收支、管债务、分类清晰、数据不丢 |
| 家庭/多场景用户 | 一套账不分家、需要多本账 | 多账本隔离、可切换 |

## 5. 用户场景

### 场景 1：记一笔支出
**前提条件：** 已启动应用并解锁
**操作流程：** 首页点「记一笔」→ 选支出 → 输入金额 → 选分类 → 填备注（可选）→ 保存
**预期结果：** 交易入库，首页结余与最近交易即时刷新

### 场景 2：记一笔借款并收款
**操作流程：** 债务页 → 新增「借出」张三 500 元 → 之后新增「收到还款」张三 200 元
**预期结果：** 张三净欠款显示 300 元

### 场景 3：导出备份
**操作流程：** 设置页 → 导出 → 生成 JSON 文件
**预期结果：** 得到含全部数据的 JSON，可导入还原

### 场景 4：应用锁
**操作流程：** 开启应用锁并设超时 → 离开超时后回来
**预期结果：** 需生物识别验证通过才可查看数据

### 场景 5：多账本切换
**操作流程：** 创建「家庭」账本 → 切换 → 记录一笔支出
**预期结果：** 该支出只出现在「家庭」账本，与「默认账本」互不影响

## 6. 功能需求详情

### F-01 收支记录
**输入：** 类型（收入/支出）、金额（元，转分存储）、分类、日期、备注（≤200 字）
**验收标准：** 金额以整数分存储无精度损失；首页显示本月结余/收支合计/最近交易；收支页可按全部/支出/收入筛选，按日期分组
**异常处理：** 金额 ≤ 0 拒绝保存；分类未选则提示

### F-02 债务管理
**输入：** 对方姓名、金额、类别（欠款/还款）、方向（借出/借入）、日期、备注
**验收标准：** 借/还平级模型（kind × direction）；明细视图按时间排序；按对象视图按人汇总净额；净额口径「借出+、借入−、收到还款−、我还款+」
**异常处理：** 姓名为空、金额 ≤ 0 拒绝保存

### F-03 分类管理
**验收标准：** 内置分类（12 支出 + 6 收入）不可删除、可改图标/颜色；自定义分类可增删改
**异常处理：** 删除分类时若有关联交易，提示迁移到其他分类

### F-04 数据导入导出
**验收标准：** 导出 JSON（version 1 格式，含 transactions/debts/categories/budgets/ledgers）；导入全量覆盖、事务原子性、字段校验
**异常处理：** 导入数据字段缺失/非法时报错不落库

### F-05 应用锁
**验收标准：** 生物识别（指纹/人脸）+ 系统凭据回退；冷启动恒锁；离开超时重锁（立即/30s/1min/5min/永不）
**异常处理：** 设备无解锁方式时提示不支持

### F-06 搜索（Phase 2）
**输入：** 从首页顶部搜索入口进入独立搜索页；搜索范围限定当前账本（不跨账本，符合 F-11 隔离）。条件字段分两组——交易：备注关键词、金额区间（min/max）、分类、日期区间、类型（收入/支出）；债务：姓名关键词、方向（借出/借入）。
**验收标准：** 结果分「交易/债务」两组；交易按备注模糊（含关键词即命中）+ 金额区间（min/max，单位分）+ 分类 + 日期区间 + 类型（收入/支出）组合过滤；债务按姓名模糊 + 方向（借出/借入）过滤；结果按时间倒序；点击结果展示不可编辑的明细。
**异常处理：** 无结果显示空态提示；金额区间 min > max 时拒绝或视为无效。

### F-07 报表统计（Phase 2）
**输入：** 统计范围限定当前账本（不跨账本）；支持月度/年度视图切换；金额口径复用已有 monthSummary/countByCategory 的整数「分」口径。
**验收标准：** 月度视图按天、年度视图按月；三类图——①收支趋势（月度按天、年度按月，折线或柱状）②分类占比（环形/饼图，收入/支出分开展示）③结余走势。
**异常处理：** 该账本无任何数据时显示空态。

### F-08 预算管理（Phase 2）
**输入：** 月度总预算（分类为空，整月）+ 分类预算（指定 categoryId）；金额单位整数「分」。
**验收标准：** 已用 = 当月该分类实际支出累计（分）；剩余 = 预算 − 已用（分）；超支 = 已用 > 预算；展示已用/剩余进度；超支时给出本地提醒（通知栏或页内形态，具体由 Architect DEC-011 决策；本需求只锁「必须在本机提醒超支、不依赖云端」）。
**异常处理：** 预算金额 ≤ 0 或未选月份拒绝保存；分类预算与总预算可并存不冲突。

### F-09 暗色模式
**验收标准：** 跟随系统 / 手动亮暗切换，全页面生效

### F-10 数据加密
**验收标准：** 本地数据库整体加密（SQLCipher）；密钥由 Android Keystore 保护；生物识别通过后取密钥解密打开数据库
> 说明：与 F-05 联动，应用锁从旧版「防偷瞄遮罩」升级为「真实解密门」。

### F-11 多账本
**验收标准：** 默认一个「默认账本」；可创建/切换多个账本；交易/债务/分类/预算按账本隔离；每账本独立统计与导入导出
> 说明：此处「多账本」指同一用户的多本账（个人/家庭/生意），不含登录/多用户账号体系。

## 7. 非功能需求

### 性能
- 冷启动（含解锁）：≤ 2 秒
- 交易/债务列表滚动流畅（千条级数据）

### 安全
- 数据库加密（F-10），密钥 Keystore 保护
- 生物识别解锁（F-05）

### 数据一致性
- 金额全程整数「分」，避免浮点误差
- 导入导出事务原子性

### 离线可用
- 所有功能离线可用，无网络依赖（本期无云端）

### 兼容性
- Android 8.0（API 26）及以上

## 8. 优先级定义

- P0：必须有，MVP 核心（F-01~F-05 + F-10/F-11 架构）
- P1：重要，MVP 内尽量做（F-09 暗色模式）
- P2：有价值，Phase 2（F-06/F-07/F-08）
- P3：远期（云端同步）
