## 1 要解决的问题

分类自学习（F-12 C2）原本把「对方全名」整串当规则词，用**原始子串包含**匹配。同一条规则换个
写法或换个门店就对不上，于是又落回「其他」：

| 已学到的原词 | 后来的新词 | 旧行为 | 新行为 |
|---|---|---|---|
| `北京轨道交通` | `北京轨道交通有限公司` | 不命中 | 命中（归一化后相等） |
| `罗森(北京)有限公司朝阳门店` | `罗森(北京)有限公司房山店` | 不命中 | 命中（归一化核心词相同） |
| `罗森(北京)有限公司朝阳门店` | `罗森(北京)有限公司北京店` | 不命中 | 命中（同上） |
| `罗森(北京)有限公司朝阳门店` | `罗森(北京)有限公司香坊店` | 不命中 | 命中（同上） |

（以上四行即用户 2026-10-13 给出的真实样例。）

## 2 算法

### 2.1 归一化 `normalize(raw): String`

1. `trim`；空输入 → `""`；
2. **剥括号内容**：中文/英文括号按对处理（深度计数），`罗森(北京)有限公司` → `罗森有限公司`；
   不配对的括号字符直接丢掉（不抛错、不吞掉括号后面的内容）；
3. **全角 → 半角**（U+FF01..U+FF5E 减 0xFEE0，U+3000 → 空格），**去空白**，**转小写**；
4. **剥后缀词**（全局替换，**长词在前**，否则「有限公司」会被「公司」先咬掉一半）：
   `有限责任公司 / 股份有限公司 / 有限公司 / 分公司 / 子公司 / 旗舰店 / 专营店 / 直营店 /
   连锁店 / 营业部 / 办事处 / 门店 / 分店 / 公司 / 集团`；
5. **去首尾标点**：`- . · 、 , ， : ： ; ； " ' * _ | / \`。

**刻意不剥裸「店 / 市 / 区 / 县 / 中心 / 广场」**：它们会咬坏正常词（`如家酒店` → `如家酒`、
`天猫超市` → `天猫超`），而误合并的代价是**静默写错账**（优先级 ①「不写错」）。

### 2.2 匹配强度 `matchStrength(ruleKeyword, counterparty): MatchStrength`

按顺序判定，先命中先返回：

| 顺序 | 条件 | 强度 | 说明 |
|---|---|---|---|
| ① | 原始串**包含**规则词 | STRONG | 与引入本算法之前的行为完全一致；**旧规则、旧库数据不迁移也照旧命中** |
| ② | 归一化后**相等** | STRONG | 同商户不同写法 / 分店后缀差异的典型情形 |
| ③ | 归一化核心词**被完整包含**且核心词长度 ≥ 3 | STRONG | 防「中」「国」这种碎片命中 |
| ④ | 归一化后**公共前缀 ≥ 2 字** | WEAK | 需要「猜」，可能猜错 |
| — | 其余 / 任一为空串 | NONE | |

阈值常量：`MIN_PREFIX = 2`、`MIN_CONTAINED_CORE = 3`。

### 2.3 使用位置（强度决定「能不能自动记账」）

- **L2 到达即记账**（`SmsBillImportUseCase.handleIncoming`）：`allowWeakRuleMatch = false`
  ⇒ **只认 STRONG**。理由：假阳性会静默写错账，优先级①压过「少打扰」。
- **用户看得见、改得动的路径**（L0/L3 全量预览确认 `importConfirmed`、L1「待确认」手工记一笔
  `confirmManual`）：`allowWeakRuleMatch = true` ⇒ WEAK 也会出建议，用户可以改。
- 命中分类必须仍在当前账本内（`rule.categoryId in validCategoryIds`），否则视为失效、继续下探。

### 2.4 多条规则命中时的排序

`ImportBillUseCase.resolveCategoryId` 第 1 步：STRONG 优先 → `coreLength`（归一化后长度，更具体
的优先）降序 → `updatedAt` 降序（ISO 字典序 == 时间序）。

### 2.5 学习侧存「核心词」

`UpsertUserCategoryRuleUseCase` 现在把 `normalize(keyword)` 作为规则词入库
（剥空或只剩 1 字时退回原始 `trim()`，避免规则词变成没法匹配的碎片）。因此每遇到一个新门店/
新写法，最多再纠正一次；老规则不动，靠 ① 原始串包含继续生效。

## 3 已知局限（诚实记账）

1. **公共前缀会误判 WEAK**：`中国移动` 与 `中国联通` 公共前缀「中国」→ WEAK。因为 WEAK 只出建议、
   不进 L2，代价可接受。
2. **后缀词表是白名单**：没列入的后缀（如「营业厅」「支行」「分号」）不会被剥。
3. **不做拼音/近义词/错别字**：需要语义猜测的一律不做（宁可落「其他」）。
4. **核心词变短**：`罗森(北京)有限公司朝阳门店` → `罗森朝阳`，理论上存在与别家同名片段相撞的可能；
   但 STRONG 判定要求「相等」或「≥3 字包含」，且 ④ 只给 WEAK，风险被限制在预览建议里。

## 4 后续优化方向（留档，未实施）

- 统计**命中率与纠正次数**（本地计数即可，不上传），据此判断是否需要扩词表 / 调阈值；
- 后缀词表可配置化（先把数据收上来再决定，避免现在过度设计）；
- 若将来引入「商户词典」（docs/20），归一化是其匹配的前置步骤，两者共用本文件的口径。
